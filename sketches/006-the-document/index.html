legion-v2 · Apache-2.0 · Node.js ≥ 20 · TypeScript

A multi-agent collective framework

An always-on process that hosts AI agents, automated services, and human users who communicate by sending messages to each other.

Legion is not a chat app you start and stop. It is a persistent process that external channels connect to simultaneously. Agents run autonomously, services react to events, and humans reach in through connectors — a web browser, Teams, Slack — to direct, approve, or monitor.

01

Design principles

The whole framework follows from a short list of commitments. They're enforced in the code, not just stated.

One process, one collective

No routing, auth, or delivery logic branches on participant type — type only describes the internal driver.

communicate is the hub

Sync calls block until a response; fire-and-forget names a replyTo participant. The MessageRouter replaces any "session" concept.

Conversations are branching trees

A keyed map of messages; the active chain is reconstructed by walking parentId. Edit, re-run, prune, compact — historical nodes remain recoverable.

AuthEngine is a pure predicate

It answers auto, requires_approval, or hidden. Approval bubbles up the call chain to an authorized approver; it fails closed if none exists.

Management is ordinary tool calls

create_agent, retire_agent, policy edits — tools gated by the caller's policy. No separate permission layer.

Connectors and MCP are not participants

Connectors are channels; MCP servers are tool sources. Core knows nothing about identity providers.

02

Key concepts

Six nouns carry the entire model.

PARTICIPANTS

Agents, services, users, mocks

Each has tool policies and approval-authority profiles. Every participant talks to every other through the same model.

CONVERSATIONS

Persistent, branching threads

Stored as key-value maps with full edit, prune, and compaction history.

COMMUNICATE

The messaging mechanism

Synchronous calls and fire-and-forget async dispatch via replyTo.

AUTHENGINE

Policy resolution

Tools absent from a participant's tools map are hidden from the LLM entirely. Approval requests bubble until they reach authority — or fail closed.

CONNECTORS

Channels to the outside

They bridge participants to external entities. Authentication is connector-internal.

MCP TOOL SOURCES

External tool registries

Declared in workspace config; tools register as mcp__<server>__<tool>.

04

Quick start

Prerequisite: Node.js 20 or later.

quickstart
$ npm install
$ npm run build
$ npm start

# first launch seeds a workspace (.legion/),
# creates a bootstrap operator, and starts
# the web server on http://127.0.0.1:3000
bootstrap operator password: 9f3a-c2…
  1. Install and build — standard npm workspaces; npm start runs the compiled runtime from packages/runtime.
  2. Log in as the operator — a random password is printed to stdout on first launch. Set LEGION_BOOTSTRAP_PASSWORD for deterministic provisioning.
  3. Open the console — the web UI at :3000 is the management surface: participants, conversations, approvals, tool policies.
  4. Wire a provider — API keys belong in ~/.config/legion/config.json or environment variables, never in workspace files.
05

Architecture

A TypeScript monorepo — npm workspaces, pure ESM, strict mode.

types

Shared TypeScript type definitions: tools, conversations, participants, config, events

core

The engine: runtimes, tools, auth, conversations, services, providers, storage

runtime

Process entry point, Fastify HTTP server, WebSocket connector

web

Vue 3 + Vite + Tailwind workspace management console

e2e

Playwright end-to-end tests against a live server

import direction: types ← core ← runtime / web — never the reverse
06

Service SDK

Any npm module can be a Legion service.

Export a LegionService object and register it in the workspace config. Services are participants like any other.

They get scoped storage, a communicate() method, and callTool() with auth enforcement.

Full SDK reference →

my-service.ts
import type { LegionService } from '@legion/core';

export const service: LegionService = {
  async start(ctx) { /* ... */ },
  async stop() { /* ... */ },
  async onMessage(msg, ctx) { /* optional */ },
};
